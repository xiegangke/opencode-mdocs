## 结论

迁移尚不完整。确认 2 个高风险、3 个中风险和 1 个低风险兼容性事项。

## Findings

1. **高：Makefile 构建入口遗漏 ls_ble**
   - `projects/remote/remote/Makefile:36-41` 未加入 `mods/ls_ble/*.c`。
   - `projects/remote/remote/Makefile:83-93` 未加入 `-I ./mods/ls_ble`。
   - CMake 已加入对应源文件和头文件目录，但传统 Make 构建会编译或链接失败。

2. **高：低功耗生命周期绕过 BT task**
   - `projects/remote/remote/mods/driver_conf/power_configure.c:223-230` 直接调用 `ble_task_sleep()`。
   - `projects/remote/remote/mods/driver_conf/power_configure.c:444-445` 直接调用 `ble_task_init()`。
   - 这绕过 ls_ble dispatcher 的单线程模型；休眠路径处于关中断区间，不能直接改成同步 dispatch，应设计队列排空及 pause/resume 握手。

3. **中：RTK/MTK 广播不是原子事务**
   - `projects/remote/remote/remote_app/src/remote_ble_if.c:461-508` 将 prepare/data/start 拆成多个异步请求。
   - `projects/remote/remote/remote_app/src/remote_ble_if.c:548-585` 在失败不可见时仍推进 timer 和广播状态。
   - 队列满或内存不足时可能形成半配置状态。

4. **中：timer 查询折叠调度错误**
   - `projects/remote/remote/appinc.h:29-39` 将所有非 OK 状态转换为 timer 未运行。
   - 旧式 `!timer_get -> timer_init` 调用可能在调度失败时重复初始化或覆盖 handle。

5. **中：HID mouse descriptor 字段不一致**
   - `projects/remote/remote/bt_if/bt_app_if.c:211-221` 声明 Usage 1..3，但 Report Count 为 5，且偏离迁移前 3 button + 5 padding 的布局。

6. **低／需协议确认：scan response 发生可观察变化**
   - `projects/remote/remote/remote_app/src/remote_ble_transaction.c:82-84,170-182` 将旧 Appearance + `IFLY RC` 改为 `LS-HID`。
   - 若主机按旧字段过滤，会有发现或识别兼容风险；源码无法确认该变化是否为明确协议需求。

## 建议验证

- 修复 Makefile 后验证 Make 与 CMake 两种构建入口。
- 压测连续语音、timer 与 GAP 回调并发下的队列深度和 heap 峰值。
- 验证 light sleep 前后请求排空、dispatcher 状态与 BLE 栈重初始化顺序。
- 在现有电视、机顶盒及产测工具上验证广播字段和 HID descriptor 兼容性。
