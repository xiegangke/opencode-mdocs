## 范围

在 HCI 错误码迁入 `mods/ls_ble/ls_ble_error.c`、工程蓝牙配置迁入 `tasks/task_btle.h` 后，分析 `bt_if` 剩余职责及后续迁移顺序。本轮未构建、未测试。

## 当前状态

- `bt_error.c` 已删除；HCI 状态字符串表和 `hci_status_code_to_string()` 位于 `mods/ls_ble/ls_ble_error.c`，并包含越界保护。
- `hci_status_code_to_string()` 的公开声明位于 `tasks/task_btle.h`，现有调用方通过 `bt_app_if.h -> bt_common.h -> task_btle.h` 可见。
- PLF heap/buffer、GAP 设备参数、PHY/连接/广播参数位于 `tasks/task_btle.h`。
- `bt_common.h` 保留协议栈公共 include，并单向 include `task_btle.h` 维持现有调用方兼容。
- CMake 与 Make 已通过 `mods/ls_ble/*.c` 纳入 `ls_ble_error.c`，并通过 `tasks` include 目录提供 `task_btle.h`，无需修改构建清单。

## 必须保持的语义

1. 系统只保留一个 BLE executor task，`ble_task_execute()` 只在该任务执行。
2. ISR schedule notify、stack transaction、app transaction 继续进入同一队列。
3. `ls_ble_dispatch` transport 与 executor context 不变。
4. ls_ble 请求和 app transaction 沿用各自的复制、完成及释放规则。
5. dispatcher 注册、BLE pre-init/init、系统 ready 同步和首次 execute 的相对顺序不变。
6. `bt_app_*`、`app_ble_connected_state()` 等公开符号先保持兼容。

## 后续迁移阶段

### 阶段 1：建立 BT task 实现文件

在 `tasks/task_btle.c` 中机械迁移 `bt_app_if.c` 的任务入口、FreeRTOS queue、ls_ble transport、dispatcher 初始化、事件投递和 app transaction 管理。先不改变函数名、消息结构和所有权逻辑；`bt_app_if.h` 保留为兼容转发头。

静态验证：符号定义唯一，`ble_task_execute()` 仍只有 BT task 内两处调用，queue 与 executor handle 只有一份。运行时验证：两种构建入口成功，启动和队列压力行为不变。

### 阶段 2：迁移任务私有类型

将 `bt_app_status_t`、task event、transaction 类型迁入 `task_btle.h`；`bt_types.h` 暂保留为兼容转发头。禁止重新形成 `task_btle.h` 到 `bt_common.h` 的反向依赖。

### 阶段 3：处理 GAP/profile 业务边界

`bt_app_if.c` 剩余的 GAP handler、profile 初始化、HID report map、设备地址和连接状态逻辑可随后迁入 `task_btle.c`，但应作为独立提交；若文件职责过重，则拆为独立 GAP/profile 模块，而不是强求只保留两个文件。

### 阶段 4：保留 callback 层独立

`bt_cb.c` 的 task/GAP/DISS/HOGPD trampoline 和 callback 表继续独立，`bt_internal.h` 继续作为内部声明边界。不要把 `bt_cb.c` 直接 include 或合并进 `task_btle.c`。

### 阶段 5：公共头收尾

`bt_common.h` 继续承载协议栈公共 include。只有出现实际耦合问题时，才把 DISS/BASS/HOGPD/OTAS include 拆到独立 profile 头。

### 阶段 6：最后处理低功耗

裸 `ble_task_sleep()`/`ble_task_init()` 不随文件迁移处理，也不得在关中断区间直接替换为同步 dispatcher wrapper。需单独设计队列排空、BT task pause/resume、栈 sleep 条件、唤醒重初始化和 dispatcher 状态恢复。

## 明确不恢复

不恢复 `btos_al`、`bt_stack_if`、`btos_def`、`BT_OS_*` 消息 ID、`bt_stack_if_get_cb()` 或第二个 BT task。
