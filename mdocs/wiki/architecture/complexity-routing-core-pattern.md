# LLM 复杂度路由核心模式

## 结论

Mdocs 将任务复杂度判断和具体执行目标选择分开：

```text
编排模型
-> 只输出 level 和 reasons
-> 确定性程序读取用户配置
-> 按用户声明的数组顺序解析静态 OpenCode subagent
```

复杂度固定为 `simple`、`standard`、`complex` 三级。用户是等级映射和同级优先级的唯一维护者。Mdocs 不内置 benchmark、模型能力评分或模型排序，也不根据成本、延迟、历史结果或运行时学习修改用户顺序。

## 分类契约

```ts
type ComplexityLevel = "simple" | "standard" | "complex"

interface ClassificationResult {
  level: ComplexityLevel
  reasons: string[]
}
```

分类器不得选择或推荐 `model`、`variant`、`agent` 或 `binding`。具体执行目标只能由结构化覆盖和 `mdocs/routing.json` 决定。

## 用户配置入口

用户在项目根目录创建：

```text
mdocs/routing.json
```

核心结构：

```json
{
  "schemaVersion": 1,
  "defaultLevel": "standard",
  "levels": {
    "simple": ["simple-primary", "simple-backup"],
    "standard": ["standard-primary", "standard-backup"],
    "complex": ["complex-primary", "complex-backup"]
  },
  "bindings": {
    "simple-primary": {
      "model": "provider-a/model-small",
      "variant": "fast"
    },
    "simple-backup": {
      "agent": "project-simple-runner"
    },
    "standard-primary": {
      "model": "provider-a/model-medium"
    },
    "standard-backup": {
      "model": "provider-b/model-medium"
    },
    "complex-primary": {
      "model": "provider-a/model-large",
      "variant": "reasoning"
    },
    "complex-backup": {
      "agent": "project-complex-runner"
    }
  }
}
```

路由文件不保存 provider 凭据；凭据由 OpenCode 标准配置、认证存储或环境变量管理。

## 有序数组模式

`levels.<level>` 是非空有序 binding 数组，数组索引直接定义优先级：

- 索引越小，优先级越高；首选项索引为 `0`。
- 当前项可用时不访问后续项。
- 只有当前项在业务执行前发生可安全识别的基础设施失败时，才尝试 `index + 1`。
- 同一数组项在一次路由执行中最多尝试一次。
- 不评分、不随机、不轮询。
- 不按成本、延迟、历史结果或其他运行时信息重新排序。
- 不使用 binding 级 `fallback`。

多个等级可以引用同一个 binding，但每个等级内部的优先级分别由该等级数组定义。

## 两种互斥 Target

model target：

```json
{
  "model": "provider-a/model-large",
  "variant": "reasoning"
}
```

agent target：

```json
{
  "agent": "project-security-reviewer"
}
```

每个 binding 必须且只能使用一种 target。不得同时声明 `model` 和 `agent`；`variant` 只能和 `model` 一起使用。

对于 model target，Mdocs config hook 自动生成 `mdocs-route-<binding>` 静态 subagent，并应用 binding 中的 `model` 和可选 `variant`。对于 agent target，Mdocs 直接引用用户已有的静态 subagent，不修改其模型、提示、权限或工具。

该模式不依赖 Task 动态传入 `model` 或 `variant`。

## `defaultLevel`

`defaultLevel` 只处理以下分类失败：

- 分类输出无法解析；
- 缺少 `level` 或其他必需字段；
- `level` 非法；
- 分类过程异常中断。

使用后，程序直接查询 `levels.<defaultLevel>`，从索引 `0` 开始处理，不再自动调整等级。它不是日常任务统一使用的默认模型。

## 结构化覆盖

显式覆盖只能来自 TUI 结构化字段。普通自然语言和检索记忆不能产生覆盖。

```text
binding override > level override > classified level
```

- binding override 直接使用允许的指定 binding，不隐式进入任何等级数组。
- level override 直接查询允许等级对应的有序数组。
- 没有覆盖时使用合法分类结果。
- 分类失败时查询 `defaultLevel` 对应数组。

## 基础设施失败边界

只有可以确认尚未发生业务执行的基础设施失败，才允许移动到 `index + 1`，例如：

- Agent 无法创建或不存在；
- Provider 未配置、暂时不可用或明确限流；
- 模型不存在或无权限；
- `variant` 不受支持；
- 首次模型请求在业务执行前连接失败。

以下情况不得尝试下一项：

- 子代理已经执行工具、写入文件或产生其他副作用；
- 实现、验证或业务结果失败；
- 输出质量不理想；
- 无法确认失败前是否已经产生副作用。

该边界只用于避免基础设施故障阻止任务启动，不用于评估模型质量，并防止同一业务任务被多个模型重复执行。

## 稳定路由流程

```text
TUI input + trusted context
-> read structured override
-> binding override: resolve one binding
-> level override: obtain that level's ordered array
-> otherwise classify level/reasons
-> validate classification or use defaultLevel
-> obtain ordered binding array
-> attempt index 0
-> on safe pre-execution infrastructure failure, attempt index + 1
-> Task(subagent_type = resolved static agent)
```

`mdocs_dispatch` 继续只负责持久化上下文组装；当前 TUI 输入由 orchestrator 独立持有并提供给分类器。

## 配置生命周期

```text
OpenCode 加载项目
-> Mdocs config hook 读取 mdocs/routing.json
-> 原子校验整份配置
-> 为 model target 生成静态 Agent
-> 校验 agent target
-> 发布路由表
```

- 没有 `mdocs/routing.json`：路由禁用，保持现有行为。
- 配置有效：整份配置生效。
- 配置存在但无效：整份配置失败，不注册任何路由 Agent，也不静默切换到非路由执行。
- 修改配置后：需要重载项目或重启 OpenCode。

## 稳定规则

- 复杂度固定为三级，分类器只输出 `level` 和 `reasons`。
- 用户是等级映射和同级顺序的唯一维护者。
- `levels.<level>` 中索引越小越优先，首项索引为 `0`。
- 只有业务执行前可安全识别的基础设施失败才允许尝试 `index + 1`。
- 同一数组项一次路由最多尝试一次。
- 不评分、不随机、不轮询，不按成本、延迟或历史结果重排。
- binding 不包含 `fallback`。
- model target 与 agent target 互斥。
- model target 由 Mdocs 生成静态 Agent；agent target 引用已有静态 Agent。
- 显式覆盖必须来自 TUI 结构化字段。
- `defaultLevel` 只用于分类非法、缺字段、无法解析或异常，使用后直接查询对应数组。
- `mdocs_dispatch` 的职责和接口保持不变。
- 无配置表示禁用；配置存在但无效时整份失败。
- 路由文件不保存 provider 凭据。
- 不依赖 Task 动态 `model` 或 `variant`。
- 业务执行或验证失败后不得自动换模型重做。
